# Política de seguridad

## Versiones mantenidas

| Versión | Soporte de seguridad |
| ------- | -------------------- |
| `1.x`   | Sí                   |
| `< 1.0` | No                   |

## Comunicar una vulnerabilidad

No publiques vulnerabilidades, tokens, identificadores ni pruebas de concepto sensibles en una issue. Utiliza el formulario privado de [reporte de vulnerabilidades de GitHub](https://github.com/sebasgrios/lucio-discord/security/advisories/new). Si GitHub no muestra el formulario, contacta con el propietario desde su perfil solicitando un canal privado sin adelantar detalles sensibles.

Incluye:

- componente y versión afectados;
- impacto observado;
- pasos mínimos para reproducirlo;
- mitigación conocida, si existe.

Se confirmará la recepción, se evaluará el impacto y se preparará una corrección antes de divulgar detalles. No incluyas credenciales reales en el reporte.

## Alcance

Son especialmente relevantes los fallos que permitan exponer credenciales, eludir permisos de servidor o canal de voz, ejecutar procesos no previstos, acceder a redes privadas, mezclar datos entre servidores o controlar una sesión sin autorización.
